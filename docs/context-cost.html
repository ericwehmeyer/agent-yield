What we found

Where it goes

1. Half of all main-session calls carry more than 249,257 tokens. A call reads its whole context before it does anything. At that size it bills a quarter of a million tokens to run a two-line command.

2. Subagents cost three times what they need to. The median subagent call carries 97,341 tokens. One given a written brief and told not to explore carries 31,618. The difference is the agent reading the repo to work out what you meant.

3. Nothing warns you, because nothing happens. Cost does not jump at a threshold. It climbs from the first call to the last. We looked for a knee in the curve. There is none.

Our rules watch how full the window is. The window is never full. This session is using 15% of it and costs 154,559 tokens a call.

The shape of it

Main sessions and subagents need different limits

We have one set for both. The median main call carries 2.6 times the median subagent call. A subagent that grows past its brief is a briefing problem; a main session that grows is a restart problem. One number, and it is wrong for one of them.

So what

565 million tokens, and what to take off it

That is what went above the limits in the table below: 19% of everything. It is the gross figure. Restarting is not free, because a fresh session reads whatever you hand it. The last method change we measured end to end returned 1.07× where per-call arithmetic promised 6.2×. The parent session ate the difference.

So halve it. It is still 280 million tokens.

How do you know where you are? Run agent-yield status. It reads the live transcript and prints what this session is costing per call.

A moment ago it called this session cheap, at 154,559 tokens a call, because 154,559 is 15% of a million-token window. The next section explains why that is wrong.

One thing still wrong

The limits are written as percentages, and they should be token counts

The code stores them as fractions of the window: COST_KNEE = 0.20. The idea was that a fraction survives a change of model.

It does not. A call carrying 200,000 tokens costs 200,000 tokens. Change the window to two million and the same call is cheap; change it to half a million and it is steep. The bill never moved. The window has nothing to do with the price.

How full the window is, and what a call costs, are different questions. Writing both as percentages is what hid this for a month. Filed as #23.
